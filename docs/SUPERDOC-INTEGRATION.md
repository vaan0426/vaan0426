Контакт: https://superdoc.bg/kontakti

## Зависимости за реално свързване
1. Официална документация, разрешен достъп, условия за интеграция и тестов календар от Супердок.
2. Реален backend с обща база, защитен админ вход и публичен HTTPS адрес. Текущите server.cjs и preview-server.ps1 сервират статични файлове; platform/core.js използва localStorage. backend/ е проектна документация, не работещ Laravel.
3. Ключове само в сървърно хранилище; никога в platform/, HTML, localStorage, клиентски ZIP или дневници. Не е нужна парола за профила на собственика.

## Правила за бъдещата реализация (изисквания, не твърдения за API)
- Супердок трябва да участва в атомарното заемане на интервал или да има един-единствен източник за записване. Само polling/webhooks след факта не премахват състезание между две едновременни заявки.
- Първоначален пълен прочит + промени по версия/маркер, странициране, периодична сверка; известия само ако официалният API ги поддържа.
- Ключ за външна резервация: доставчик + календар + външен ID. Повторно получено събитие не създава втора резервация; остаряла версия не отменя по-нова.
- Поддържане на създаване, преместване, отказване. Съществуващ конфликт се маркира за преглед, без тихо изтриване на местна резервация.
- Проверка за припокриване на интервали на един специалист: start < otherEnd и end > otherStart. Еднакви slot IDs не са достатъчни.
- Съхранение UTC, показване Europe/Sofia; тестове за лятно/зимно време, различни продължителности и съседни неприпокриващи се часове.
- При недостъпен или несверен календар сайтът не потвърждава нови реални резервации. Не освобождава непроверени заети интервали.
- Изходящите промени имат идемпотентен ключ и сверка при неясен резултат след timeout; без сляпо повторно записване.
- Админ статуси: не е настроено / проверка / свързано / остарели данни / грешка, с реални последна успешна сверка и брой конфликти. „Свързано“ само след удостоверена сървърна проверка.
- Публичният сайт получава само свободни интервали, без имена и медицински бележки. Панелът показва минимално необходимите данни.

## Приемателни проверки преди активиране
Две едновременни заявки от различни системи → само една потвърдена; повторен webhook → без дублиране; преместване/отказване → правилно заемане/освобождаване; пропуснато известие → поправено при сверка; повреден подпис → отхвърлен; timeout след успешно записване → намерена същата резервация; нова версия преди стара → запазена новата; недостъпна услуга → без непроверено потвърждение.
Не са изпълнени тестове срещу Супердок, тъй като няма официален API договор или достъп.
